## Method and limits

- Ran deptry 0.25.1 over `src workflows scripts` in an isolated tool environment, without installing or importing the application. Raw run: exit 1, 404 findings (349 DEP001, 11 DEP002, 44 DEP004). Repeated with explicit distribution/module aliases and known local modules: exit 1, 326 findings (278 DEP001, 4 DEP002, 44 DEP004). These are audit findings, not a passing check or 326 confirmed defects.
- Without installed application metadata, DEP001 includes locked transitive dependencies, not necessarily missing install artifacts. DEP002 also misidentifies the split `langgraph.checkpoint.postgres` namespace even after mapping it; source imports prove it is used. Mapped DEP002 reports numba, python-multipart, langgraph-checkpoint-postgres and number-parser. Only the last has neither a direct importer nor a separately established runtime/dependency role in this scope.
- Built an AST graph from all 918 Python files under src, 7 under workflows and 57 under scripts, plus the single packaged `web/argus_display_contract` module for local resolution: 983 files, 8,362 deduplicated local edges. All files parsed; no unresolved argus/workflows imports. Resolved absolute/relative imports, `from package import submodule`, and package initializers; excluded TYPE_CHECKING-only branches from reachability. The graph retains lazy/function-local and conditional imports, including the engine-launch `__getattr__` adapter. It is not a call graph or a general dynamic-import analysis; TYPE_CHECKING recognition is syntactic, and external package imports are not traversed.
- **Yes means conservative static module reach**, not that production calls every function, imports every lazy branch at startup, or enables every feature. API root: `argus.api.main`; worker root: `workflows.document_worker`. Their closures contain 905 and 805 local modules respectively. No app startup, tests with real providers, runtime import probe, hosted inspection or deployment was attempted. Exact invocation and platform-specific installed distributions remain unmeasured.
- The table covers every one of the 30 non-Python main declarations, scipy from the issue, and all additional third-party modules directly imported in the requested scan. It is not a census of every indirect wheel in poetry.lock. Braces list exact filenames within one directory, not a wildcard. TYPE_CHECKING importers remain in the importer census even though they do not create runtime edges. Production reach and installation are distinguished for framework/CLI/transitive exceptions.
- Runtime exceptions were checked against `render.yaml` (API launches uvicorn, document reader launches its module), API File/Form usages, and poetry.lock. The lock records vectorbt → numba/scipy/scikit-learn and scikit-learn → scipy/joblib. Removing a main pin alone does not remove those indirect requirements. scipy has **no direct source importer** in this snapshot; runner.py imports vectorbt.
- Reproduction commands, alias mapping, the complete standalone graph scanner, output totals and verification evidence are in the draft PR body. Scratch scripts/results are not committed.

## Import-path evidence and sequencing

The paths below are source edges, not runtime call traces. Function-local edges explain why the worker's static closure is much larger than its document behavior.

- API → `api.routers.tool_results` → `agent_runtime.answer_calculation` → `domain.engine` → `domain.backtesting.runner` → vectorbt. S3 is not safely reducible to deleting one dependency line while these callers remain.
- Worker → `domain.ingestion.documents.config` → `api.financial_accounts` (for TRUE_VALUES) → `api.state` → `agent_runtime.tools.real_backtest` (function-local) → `domain.engine_launch.adapter` → `domain.engine` → runner → vectorbt. Move/separate retained helpers under the S1/S4/S5 boundaries before removing legacy modules. A default-off feature does not erase these source edges.
- Worker → `workflows.document_job` → `domain.supabase_gateway` → `domain.supabase_public_excerpts` → `domain.public_excerpts` → `domain.backtesting.rules` → `domain.backtesting.rules.series` → `domain.indicator_execution` → pandas-ta-classic (function-local). Retained shared excerpt code is another removal constraint.
- API → `api.routers.discovery` → `domain.market_data` → provider → joblib / alpaca. Worker → document config → financial_accounts → `api.schemas` → `api.artifact_presentation` → `agent_runtime.research_grounded` → market_data/provider reaches the same owners.
- API → `api.app_setup` → `api.personalization_memory` → `api.personalization_memory_index` → mem0 / langchain (function-local). Neither package has a direct reachable importer in the worker graph.
- Retained `api.whatsapp` → `agent_runtime.business.runner` → `agent_runtime.graph.workflow` → langgraph. BusinessTurnRunner calls `build_workflow(business_runtime=stages)` at runner.py:141, so langgraph itself remains a retained WhatsApp requirement after legacy stages are removed.
- Worker → document config → `llm.openrouter` → `llm.openrouter_langchain` → langchain-openrouter. Retained `agent_runtime.business.runner` and `business.interpretation` also import that shared facade. S5 cannot remove this package wholesale without separating retained consumers.

The next removal proposals must delete each obsolete slice and its now-unused dependencies together, preserve documents/WhatsApp/email/Business/month close, and repeat this measurement on their current base. This report does not authorize those proposals, move any dependency group, or establish that every static-reachable legacy path is an active product feature.
